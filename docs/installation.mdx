# Installation

JackpotKit publishes five packages. Install the renderer for your platform plus the packages you
import from directly.

| Package                    | Use it for                                                                    |
| -------------------------- | ----------------------------------------------------------------------------- |
| `@jackpotkit/react`        | React web components and hooks (SVG, Canvas, CSS motion). SSR-safe.           |
| `@jackpotkit/react-native` | React Native components and hooks (Reanimated, SVG, Skia for Scratch Card).   |
| `@jackpotkit/core`         | Headless engines, result types, random sources, and errors. No UI dependency. |
| `@jackpotkit/theme`        | `defaultTheme`, `neonTheme`, `createJackpotTheme`, and theme types.           |
| `@jackpotkit/testing`      | Deterministic random sources, mock providers, and fixtures for your tests.    |

All packages are **ESM-only** and require **React 19.2.3 or later** (`react` peer `^19.2.3`). The
renderers already depend on `@jackpotkit/core` and `@jackpotkit/theme`; list them in your own
`package.json` as well whenever you import from them, because pnpm and Yarn Plug'n'Play only let you
import packages you declare.

## React web

```npm
npm install @jackpotkit/react @jackpotkit/core @jackpotkit/theme
```

`react` and `react-dom` (`^19.2.3`) are peer dependencies; install them if your project does not
already have them. There is no native, Expo, or Skia dependency on the web. See
[React web renderers](./react-web.md) for what each game uses in the browser.

### Next.js and other SSR frameworks

Every export is safe to import and render on the server: package initialization never touches
`window`, `document`, Canvas, or `matchMedia`, which are read only after mount. The games are
interactive, so render them from a client component:

<include lang="tsx">../apps/docs/examples/web/next-client-component.tsx</include>

No `transpilePackages` entry is needed; the packages ship compiled ES modules with type
declarations. The system reduced-motion preference is read after mount, so the server and the first
client render agree.

## React Native

```npm
npm install @jackpotkit/react-native @jackpotkit/core @jackpotkit/theme react-native-reanimated react-native-worklets react-native-gesture-handler react-native-svg
```

| Peer dependency                | Supported range | Required                                |
| ------------------------------ | --------------- | --------------------------------------- |
| `react`                        | `^19.2.3`       | Yes                                     |
| `react-native`                 | `>=0.83 <0.87`  | Yes                                     |
| `react-native-reanimated`      | `>=4.5 <5`      | Yes                                     |
| `react-native-worklets`        | `>=0.10 <0.12`  | Yes                                     |
| `react-native-gesture-handler` | `>=2.32 <4`     | Yes                                     |
| `react-native-svg`             | `>=15.15 <16`   | Yes                                     |
| `@shopify/react-native-skia`   | `>=2.6 <3`      | Only for Scratch Card (`/scratch-card`) |

Reanimated 4 runs its animations through `react-native-worklets`, which needs its Babel plugin in a
bare React Native app. Add it last in `babel.config.js`:

```js title="babel.config.js"
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  plugins: ['react-native-worklets/plugin'],
};
```

Gesture Handler needs `GestureHandlerRootView` near the root of your app (see the Expo layout
below). Rebuild the native app after installing native peers; a JavaScript reload is not enough.

### Scratch Card and Skia

Scratch Card is the only game that draws with Skia, and it is the only game that is not exported
from the package root. Install Skia only if you use it, and import it from its exact subpath:

```npm
npm install @shopify/react-native-skia
```

```tsx
import { ScratchCard } from '@jackpotkit/react-native/scratch-card';
```

Apps that never import `@jackpotkit/react-native/scratch-card` do not need Skia and never load it.

## Expo

Let Expo choose native peer versions that match your SDK, then add the JackpotKit packages:

```bash
npx expo install react-native-reanimated react-native-worklets react-native-gesture-handler react-native-svg
npx expo install @shopify/react-native-skia   # only for Scratch Card
npm install @jackpotkit/react-native @jackpotkit/core @jackpotkit/theme
```

`babel-preset-expo` adds the worklets Babel plugin for you, so an Expo app needs no
`babel.config.js` change. The repository's Expo gallery (`apps/expo-example`, Expo SDK 57) has no
Babel configuration at all. A root layout with Gesture Handler and a shared theme:

<include lang="tsx">../apps/docs/examples/native/root-layout.tsx</include>

Expo Go ships its own versions of these native libraries for its SDK. If Expo Go reports a missing
or mismatched native module, use a [development build](https://docs.expo.dev/develop/development-builds/introduction/).

### Expo web

Every game except Scratch Card runs on Expo web through react-native-web. Scratch Card needs Skia's
CanvasKit WebAssembly build on the web; see [Scratch Card: Expo web](./scratch-card.mdx#expo-web)
and [Troubleshooting](./troubleshooting.md#skia-on-the-web-canvaskit).
